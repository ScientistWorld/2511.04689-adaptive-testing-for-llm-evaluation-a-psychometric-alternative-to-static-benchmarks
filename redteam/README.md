# Scoring audit

Every candidate is implemented by its `method.py` and executed by its `run.sh`.
Run the bundle with `bash redteam/run_all.sh` on a compute node. Dependencies
are the gym's existing Python and NumPy installation; no package changes.

The bundle preserves cases that already have a `status.json`. To replay a case
regardless of saved status, run its entry point on a compute node, for example:

```sh
bash redteam/shortcut_constant_one_item/run.sh
```

If the ignored seed-123 method artifacts are absent, the harness first runs
`redteam/reference_seed123/run.sh` to regenerate them from visible code. Replays
therefore work from a clean checkout and do not need the gym's old checkpoints.
This prerequisite can take several minutes. Numerical computations belong in
submitted jobs, as in the original audit.

`harness.py` stages candidate-owned checkpoint/data artifacts, lets the method
process exit, runs the visible train scorer, and starts the unmodified
`bash scripts/evaluate_test.sh` with **no arguments** in a separate process.
It then restores the original checkpoints, scores and any changed data.
There are no evaluator or environment modifications and no surviving method
processes. `scores_test.json` and `status.json` in each candidate directory are
the test evidence; `rank.json` applies the requested raw weighted rank formula.

Candidate code uses the supplied visible data, baseline and improve-mode method.
The only hidden files read by the audit are for inspecting the scoring contract
and executing the restored test; they are never imported by candidate code.
`reference_scores_test.json` and `rank_reference.json` are audit/reporting inputs,
never candidate inputs. Reused reference outputs are generated by seed 123 of
the visible method; they can be regenerated by its run script.

The three named proposed operating points are ranked separately and also
summed. Baseline deltas and a sum including the baseline are retained so that
baseline-changing shortcuts are not mistaken for improvements if a downstream
ranker includes baseline outputs. A result with nonfinite rank is not treated
as a demonstrated high-scoring shortcut.

The reference uses exactly the original 241-point quadrature, probabilities,
RNG sequence, item selection and stopping logic. Its grid probability array is
memoized per item bank to fit the audit in one CPU job. Seed-123 scores are
compared against the frozen reference to verify the cache preserves results.
No paper contents, unavailable reference checkpoints or hidden identities are
used to construct any candidate. The empirical-prior variants fit a Gaussian
prior using only the even-hash train identities defined by visible code.
